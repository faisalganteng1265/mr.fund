> **For agentic workers:** work the tasks in order. Read the skill named in each task's **Skills** line before starting it (`.claude/skills/<name>/SKILL.md`). Steps use checkbox syntax. CLAUDE.md rules outrank this plan: no commit, push, account creation, deployment or mainnet action without the explicit authorization named in CLAUDE.md.

**Goal:** finish Phase 0 evidence work that needs no founder input, and build the tested finance engine and Rhea read adapter (Phase 1) so every number in the never-cut demo can be produced from a snapshot.

**Architecture:** `packages/shared` holds types and unit math; `packages/engine` is pure functions over `PositionSnapshot`; `packages/rhea` is the only package that does I/O for reads. Seams and import rules are in ARCHITECTURE "Codebase structure and interfaces". Each engine file is a deep module: one small exported function set, all rounding and unit rules hidden behind it.

**Tech stack:** TypeScript 7.0.2 strict, `bigint` money math, Vitest 5.1.0 (property tests via `fast-check`, added in P1.2), pnpm 12 workspace, Rust workspace in `contracts/` (already scaffolded, P0.7).

**Specs:** [PRD](../PRD.md) F2, F3; [ARCHITECTURE](../technical/ARCHITECTURE.md) "Core types", "Engine functions"; [BUILD-PLAN](../BUILD-PLAN.md) Phases 0 and 1; [SMART-CONTRACT](../technical/SMART-CONTRACT.md) for P0.3/P0.4.

## Global constraints

- Amounts are `bigint` token atomic units; Rhea internal units (`atomic × 10^extraDecimals`) are a separate use and are converted only by `toInternal` / `toAtomic`. No `number` for money, no floating point.
- Rounding is conservative: health rounds **down**, debt rounds **up**, liquidation price rounds **up**.
- Missing or stale input returns a typed `EngineError`, never a default value. `Computed<T>` always carries `inputs`, `assumptions`, `dataAgeMs`.
- Fixture data is labelled with network, block and date and is never shown as live.
- Banned in copy and test names: "never get liquidated", "guaranteed yield", "safe", "risk-free", "free borrowing".
- Import rules: `engine` imports only `shared`; `rhea` and `guardian-client` import `shared`; no package here imports a signer.
- Evidence goes on the BUILD-PLAN task's `Evidence:` line in the same commit as the code. Never call an unrun check passing.
- Commits: `type(scope): outcome in plain words`, English, no AI attribution, one logical unit per commit, **only when the user asks**.

## Review focus

Inputs the spec implies but no BUILD-PLAN test names; each gets a test in the owning task.

1. **Zero debt or zero collateral** → `"no_debt"` (not a division by zero); debt with zero collateral → `0` bps. (P1.2)
2. **Asset with `volatilityRatioBps = 0`** on a debt asset would divide by zero → `unsupported_asset`. (P1.2)
3. **`default_price` assets** (testnet): `publishTimeMs: null` skips the freshness check, but the result's `assumptions` must say the price is fixed. (P1.2)
4. **Amount strings** `""`, `"-5"`, `"1.5"`, `"1e6"`, `" 100"`, `"007"` are rejected by `parseAtomic`. (P1.1)
5. **Indonesian and Spanish number formatting** (`1.234,5` / `1 234,5`) must come out of `formatUnits` so the P3.2 checker can normalize it. (P1.1)

### Task B2: Health factor and liquidation price (P1.2)

**Skills:** test-driven-development, requesting-code-review (money path review before ticking).
**Files:** Create `packages/engine/src/health.ts`, `packages/engine/test/{health,health.props}.test.ts`, `fixtures/rhea/testnet-account-sample.json` (from A1/B4 recordings; if no real account exists yet, build the vector by hand and mark `_provenance.kind: "hand-computed"`).
**Interfaces (produces):**

```ts
export function healthBps(s: PositionSnapshot, nowMs: number): Result<Computed<Bps | "no_debt">, EngineError>;
export function liquidationPrice(s: PositionSnapshot, collateralTokenId: AccountId, nowMs: number): Result<Computed<Price>, EngineError>;
export function liquidationDiscountBps(healthBps: Bps): Bps;   // (10000 - h) / 2, 0 when h >= 10000
```

Formula (ARCHITECTURE): `C = Σ value(collateral_i)·r_i`, `B = Σ value(debt_j)/r_j`, `r = volatilityRatioBps/10000`, health `= C/B`. Compute in a 1e18-scaled integer domain; collateral terms floor, debt terms ceil; final division floors.
**Freshness:** price with `source: "oracle"` older than `MAX_DATA_AGE_MS` → `stale_price`; `source: "default_price"` skips the age check and adds the assumption `"<symbol> uses a fixed price"`.

- [ ] **Step 1 (failing tests):** `liquidationDiscountBps(8750) === 625`; `liquidationDiscountBps(10000) === 0`; hand-computed vector (record the arithmetic in the test comment); `no_debt` when `borrowed` is empty; zero collateral with debt → `0`; `missing_price`; `stale_price` (publish time older than the limit by 1 ms); `unsupported_asset` for an unknown token and for `volatilityRatioBps === 0` on a debt asset; supplied-but-not-collateral balance is excluded from `C`; `default_price` adds the fixed-price assumption; `liquidationPrice` evaluated at that price makes `healthBps` land at or just below 10000, never above.
- [ ] **Step 2 (property tests, fast-check):** more collateral never lowers health; repaying never lowers health; a lower collateral price never raises health.
- [ ] **Step 3:** `npx vitest run packages/engine` → FAIL, then implement `health.ts`, then PASS.
- [ ] **Step 4:** Review the diff with `requesting-code-review`; fix findings. Tick P1.2 with the test summary and fixture provenance.
